# Decision D-038 — Phase-specific derived-data folders

> **Historical interim-layout decision:** D-049 supersedes D-038's practice of retaining a separate interim directory for each processing phase. The current OBIS family has only `data/interim/obis/cleaning/`; Bio-ORACLE now has only `data/interim/bio_oracle/cleaning/`. Its earlier `source_validation/` state can be regenerated from the raw source run and staging script. The integrated dataset has a planned single-file destination and has not been generated. See [D-049](2026-10-11-decision-interim-one-current-dataset.md) for the active rule. The historical decision below is preserved as evidence of the earlier workflow.

- **ID:** D-038
- **Date:** 8 October 2026
- **Question:** How should source data be arranged across successive interim phases, and which sources are implemented in this branch?
- **Context:** The user clarified that each source-specific transformation phase should have its own stable folder beneath the source's interim directory. The earlier D-037 convention used one top-level derived file per source. At the time of D-038, the user also explicitly limited code in this branch to OBIS and asked that Bio-ORACLE remain documentation-only. The subsequent request recorded in D-046 supersedes that implementation boundary for environmental source intake only.
- **Options considered:** Keep one interim file per source; create timestamped output folders for every run; or create a stable source/phase hierarchy, replacing outputs within each phase and using fixed paths between phases.
- **Evidence and source references:** The project's analytical workflow separates acquisition, source quality, cleaning, integration and later preparation. The data conventions require preservation of original payloads and reproducible transformation lineage. See [data storage and provenance](../data/data-storage-and-provenance.md) and the [ML workflow](../ml/ml-workflow-and-evidence-gates.md).
- **Decision:** Keep timestamps in raw acquisition snapshots. At the first OBIS raw-to-interim CSV handoff, accept the selected raw CSV path and write a validated, byte-for-byte copy to `data/interim/obis/source_validation/occurrences.csv`, with a timestamp-free `manifest.json` beside it. Put each later OBIS transformation in its own stable subfolder under `data/interim/obis/`; scripts read the preceding phase's fixed output and write their own fixed destination. At the time, Bio-ORACLE had the same source/phase path convention but no intake code. D-046 and D-047 later authorise Bio-ORACLE source intake; the first Bio-ORACLE handoff accepts one selected complete catalogue run manifest and writes unchanged NetCDF payload and receipt copies beneath `data/interim/bio_oracle/source_validation/<dataset-id>/`, with the copied run manifest and a stable aggregate `manifest.json`. Later phases keep fixed input/output paths under `data/interim/bio_oracle/`. Cross-source integration and processed outputs use fixed, timestamp-free destinations when implemented; the planned analysis-ready destination remains `data/processed/modeling_dataset.parquet`.
- **Rationale:** A source/phase hierarchy preserves the lineage and purpose of each derived version. Selecting the raw run once makes the first OBIS handoff reusable; fixed paths between phases prevent downstream scripts from depending on typed timestamps. Replacing output within a phase avoids accumulating copies from repeated runs.
- **Consequences and limitations at the time:** D-038 described the initial OBIS byte-copy handoff and a folder for each phase. The Bio-ORACLE handoff was later implemented and the user reports running it; its aggregate manifest records 356 layers and 2,392 variables, and the local inventory contained copied payloads and receipts. Those hashes were not independently recalculated during an earlier UX update; the full 714-file bundle was subsequently verified during cleaning. Under D-049, the OBIS handoff now records a source manifest without making a second CSV, and prior interim phase datasets are no longer retained. OBIS cleaning and Bio-ORACLE structural/numerical cleaning are implemented. Environmental extraction, integration and modelling remain pending.
- **Status:** Accepted refinement of D-037 when established. Its original OBIS-only implementation boundary was superseded by D-046 and expanded by D-047. D-049 supersedes D-038's separate interim dataset retention convention; the raw timestamp and selected-input provenance guidance remains relevant.
