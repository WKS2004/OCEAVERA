# Decision: Branch CI and data-intake syntax check

- **ID:** D-040
- **Date:** 2026-10-08
- **Question:** Which repository checks should run on this branch and the current biological data collection section?
- **Context:** The existing repository-check workflow ran the maintained structural helper for pull requests, pushes to `main` and manual dispatch. The current branch contains the OBIS API downloader, JSON-to-CSV converter and raw-to-interim handoff scripts. No project decision authorises automated dataset retrieval in CI.
- **Options considered:** Keep the existing trigger and checks unchanged; add a separate branch-specific workflow; extend the existing workflow to all branch pushes and syntax-check the current intake/handoff scripts.
- **Evidence and source references:** Explicit user request on 8 October 2026; the current [repository checks workflow](../../.github/workflows/ci.yml), [OBIS intake and handoff scripts](../../src/README.md), and [workflow guide](../project/github-workflows.md). Repository policy prohibits branch-name allowlists and pattern rules.
- **Decision:** Extend the existing repository-check workflow to run on pull requests, every branch push and manual dispatch. Keep the existing structural helper and compile the current data-intake and handoff scripts: `src/data_collection/obis_occurrences.py`, `src/data_collection/obis_json_to_csv.py`, `src/data_collection/bio_oracle_layers.py`, `src/data_preparation/stage_obis_csv.py` and `src/data_preparation/stage_bio_oracle_layers.py`. D-046 added the Bio-ORACLE collector to the original OBIS syntax-check list; the Bio-ORACLE source-validation handoff is now included under D-038. Skip the check job for tag pushes. Do not create a separate workflow or any data-acquisition job.
- **Rationale:** The checks now run when this branch changes without introducing a branch allowlist. Syntax compilation provides a small, deterministic check for the active Python scripts while avoiding their runtime side effects.
- **Consequences and limitations:** The workflow retains `contents: read` token permission and uses the existing Python 3.14 baseline. Compilation checks syntax only; it does not establish runtime correctness, API completeness, or lossless data retrieval. `py_compile` may create ignored bytecode in the ephemeral runner workspace. The workflow does not run acquisition, make OBIS or Bio-ORACLE requests, download datasets or install project packages. Hosted execution remains pending.
- **Status:** accepted
- **Affected documents and artefacts:** `.github/workflows/ci.yml`, `README.md`, `docs/project/github-workflows.md`, `docs/project/repository-readiness-and-alignment.md`, `docs/project/decision-register.md`, `docs/records/2026-10-08-decision-ci-branch-and-intake-syntax-checks.md`, `docs/ai-contribution/sanudaabey-ai-usage.md`
- **Supersedes / superseded by, if applicable:** Refines D-029's trigger and repository-check scope. D-046 extends its syntax-check list to the Bio-ORACLE collector, and the later D-038 source-validation utility is also compiled; the workflow still does not run data acquisition.
