# Decision D-047 — Catalog-wide Bio-ORACLE v3 regional intake

- **ID:** D-047
- **Date:** 9 October 2026
- **Question:** How should the Bio-ORACLE source intake cover the requested Sri Lankan marine area, every available variable and field, and the full 2000–2100 v3 period?
- **Context:** D-046 implemented one small OceanTemperature feasibility query. The user expanded the requested acquisition to every Sri Lanka-related marine layer and variable for the complete Bio-ORACLE v3 time horizon. D-048 resolves the source-collection extent as the rectangle made from the published Sri Lankan EEZ feature's minimum and maximum coordinates; the earlier 79–82°E, 5–10°N example remains unselected.
- **Options considered:** Continue downloading one manually selected variable at a time; request complete global files; or inventory the publisher's active gridded catalogue, select all v3 regional layers using explicit geographic bounds, and request every data variable in each selected dataset.
- **Evidence and source references:** Bio-ORACLE documents global 0.05-degree products, physical/chemical/biological variables, temporal statistics, surface and benthic strata, topographic layers, present-day climatologies and six future SSP families. Its overview describes a 2000–2100 product horizon; the current ERDDAP v3 metadata retrieved for this intake exposes baseline coordinates at 2000 and 2010 and eight scenario coordinates from 2020 through 2090, with no 2100 coordinate in the selected layers. See the [Bio-ORACLE layer documentation](https://www.bio-oracle.org/documentation.php), its [download manager](https://www.bio-oracle.org/downloads-to-email.php), the publisher's [ERDDAP all-datasets catalogue](https://erddap.bio-oracle.org/erddap/tabledap/allDatasets.html), [ERDDAP REST documentation](https://erddap.bio-oracle.org/erddap/rest.html), and the [regional intake source record](2026-10-09-source-bio-oracle-sri-lanka-catalog.md).
- **Decision:** Extend the standard-library collector with a metadata-only catalogue inventory and an explicit resumable bulk-download command. Include Bio-ORACLE v3 baseline layers, every v3 SSP scenario, and the static `terrain_characteristics` grid when they intersect the D-048 longitude and latitude bounds. For each dataset, retain every gridded data variable in the publisher's NetCDF response, use every available value on additional axes, and apply the requested 2000–2100 window to each layer's actual time coordinates. The query selects only coordinates the publisher provides: two baseline decade labels (2000 and 2010) and SSP decade labels from 2020 through 2090. The latter is the start of the final decade that reaches the 2100 horizon, not a separate 2100 timestamp. Preserve each response unchanged with its own query/checksum manifest, cache source metadata for resumability, and update a local run manifest as layers complete or fail. Future SSP layers remain projections; their acquisition does not authorise future-climate species modelling, which remains outside current assignment scope.
- **Rationale:** A catalogue-driven plan covers source variables, statistics, depth strata, scenarios and static terrain products without silently converting the publisher's gridded data or guessing the regional boundary.
- **Time-axis clarification (9 October 2026):** A read-only audit of all 356 layer metadata caches found two baseline labels (2000 and 2010), eight SSP labels (2020–2090) and one static terrain coordinate. Representative downloaded NetCDF arrays confirm those labels. Bio-ORACLE documents ten decadal steps through 2100, defines present-day conditions as 2000–2020, offers the 2000–2010 and 2010–2020 decade selections, and states that yearly data are not provided. The 2090 SSP label is the final decade reaching 2100 under that scheme; there is no separate 2100 timestamp. The catalog-level 2010–2020 baseline is documented, but because per-layer titles end in 2018, 2019 or 2020 and the ERDDAP axis metadata does not specify each slice's averaging window, inclusion through 2020 remains unverified for every layer. Full evidence is in the [regional source record](2026-10-09-source-bio-oracle-sri-lanka-catalog.md).
- **Consequences and limitations:** The collector originally exposed separate metadata-inventory and bulk-download commands. A later implementation update made it a fixed, no-option entry point: running the script uses the D-048 rectangle and 2000–2100 window, plans the live catalogue internally, and starts the regional download when the plan has no unresolved layers. This changes invocation, not the selected acquisition scope. The user-facing run now reports its stages, existing-file checks, periodic transfer progress and a final recovery summary; interrupted transfers are retried for up to three attempts total, and only hash-verified complete responses are reused. ERDDAP accepts a rectangular coordinate subset; this rectangle may include land and waters outside the EEZ polygon, and no marine mask or polygon clipping is applied at intake. Each response has a 512 MiB safety limit; incomplete runs remain marked partial or in progress. The future SSP axis has labels through 2090, covering the final decade through the publisher's 2100 horizon; there is no separate 2100 timestamp. Bio-ORACLE does not provide annual values. The exact 2010–2020 coverage for each individual baseline layer remains unresolved from the current metadata. The earlier single-layer feasibility payload and its local manifest were removed on 9 October at the user's request; that source record preserves historical measurements.
- **Status:** The latest Python-file acquisition completed all 356 regional v3 grids and 2,392 variables (4,017,532,960 NetCDF bytes), with zero failed or pending layers. Independent byte-count, SHA-256, NetCDF-signature and receipt-scope checks passed for every payload. The user deleted the earlier complete snapshot and subsequent partial manual snapshot before this final run. Its run ID and audit are in the [regional intake source record](2026-10-09-source-bio-oracle-sri-lanka-catalog.md).
