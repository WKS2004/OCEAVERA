# Decision D-050 — Initial OBIS and Bio-ORACLE integration scope

> **Historical status:** Superseded on 15 October 2026 by [D-051](2026-10-15-decision-spatiotemporal-integration-rework.md). The implementation script, interim GeoParquet and branch notebook described below were retired after the replacement full and temporal outputs passed read-back checks. This record and its audit files remain historical evidence.

- **ID:** D-050
- **Date:** 12 October 2026
- **Question:** How should the cleaned OBIS observations be integrated with the current Bio-ORACLE baseline and terrain products before species-specific selection or target construction?
- **Context:** The user requested implementation and execution of the supplied integration instructions. The task requires all current cleaned OBIS rows, six selected environmental products, transparent nearest-cell mapping and missingness indicators, and no species filter, target, background sample, modelling or source modification. D-049 sets the fixed integrated dataset path. The project requires explicit user authorisation for Python environment or package operations.
- **Options considered:**
  - Preserve every cleaned OBIS row and map it to the nearest in-extent Bio-ORACLE grid-cell centre, retaining null measurements and explicit statuses.
  - Restrict rows to provisional focal species before integration.
  - Clamp out-of-extent points to edge cells, replace masked cells with farther values, or infer an ocean mask from undocumented `landmass` codes.
- **Evidence and source references:** User-supplied integration instructions; current OBIS cleaning output and manifest; current Bio-ORACLE cleaning manifest and summary; [prepublication audit](2026-10-12-obis-bio-oracle-prepublication-audit.md) and its [machine-readable results](2026-10-12-obis-bio-oracle-prepublication-audit.json); [D-049 storage decision](2026-10-11-decision-interim-one-current-dataset.md); [data storage conventions](../data/data-storage-and-provenance.md).
- **Decision:** Integrate all 23,371 rows from the current cleaned OBIS CSV without filtering or deduplication. Use the five selected surface baseline products for stored dynamic coordinate labels 2000 and 2010, and static terrain for bathymetry. Match valid WGS84 observation coordinates to the nearest in-extent cell centre on the actual increasing Bio-ORACLE axes; use longitude as geometry X and latitude as Y; retain original coordinates, matched row/column and cell centre, and compute haversine distance in metres. Do not clamp points outside the outer half-cell boundaries, search past a masked cell, impute, interpolate, average time labels, change bathymetry sign, or create target/background fields. Convert declared fill/missing values to null and retain unmatched records with explicit statuses. Treat selected-layer non-fill availability only as an empirical coverage indicator, not an authoritative marine mask. The fixed GeoParquet destination is `data/interim/integrated/integrated_dataset.parquet` under D-049.
- **Rationale:** This follows the requested all-record integration stage and preserves observation lineage and source quality fields while keeping spatial assignment and environmental coverage distinct from occurrence meaning. The selected products share the verified grid and surface context; bathymetry is static. Stored year labels are not exact annual observations.
- **Consequences and limitations:** The full in-memory audit processed 23,371 rows, preserved all source rows and coordinates, found 16,840 complete matches and 6,531 cells where all selected environmental fields are fill, and found no out-of-extent, partial-missing or extraction-error rows. The GeoParquet was published to `data/interim/integrated/integrated_dataset.parquet`; it contains 23,371 rows × 133 columns, GeoParquet 1.1.0 WKB Point geometry, EPSG:4326 and ZSTD compression. Read-back checks verified unique source IDs, all 112 source attributes, the complete one-based row sequence, coordinates, schema types, spatial assignments, cell centres, distances, status counts and environmental nulls. The existing `OCEAVERA` Python 3.14.8 environment supplied the pinned `geopandas==1.2.0` and `pyarrow==26.0.0`; no environment or package changes were made. The O₂ and NO₃ source unit strings `MMol' 'M-3` remain ambiguous and are preserved without conversion. The empirical coverage mask is not an independently verified marine boundary. This decision does not select a focal species, define absences, approve records as species presences or training labels, or claim supervised-model readiness.
- **Status:** The initial integration method, GeoParquet publication and saved-file validation are complete. Scientific eligibility, marine-domain interpretation and all later analytical decisions remain open.
