# Decision D-046 — Start Bio-ORACLE environmental data intake

- **ID:** D-046
- **Date:** 8 October 2026
- **Question:** How should the authorised environmental data collection phase begin while the focal species, modelling domain and final predictor set remain open?
- **Context:** The user explicitly requested the environmental data collection phase and immediate implementation. D-038 had limited this branch to OBIS code and left Bio-ORACLE documentation-only. That later implementation boundary can now be superseded without changing D-038's stable, phase-specific derived-data path convention.
- **Options considered:** Wait for final species/domain decisions before implementing any intake; download whole global layers; or implement a source-specific, standard-library collector that requires an explicit layer, variable and bounded coordinate window, while treating its first query as feasibility evidence only.
- **Evidence and source references:** Bio-ORACLE documents NetCDF source layers and ERDDAP-based subsetting in its [data-layer documentation](https://www.bio-oracle.org/documentation.php). The ERDDAP metadata page for [OceanTemperature baseline 2000–2019, surface](https://erddap.bio-oracle.org/erddap/info/thetao_baseline_2000_2019_depthsurf/index.html) identifies the v3.0 source, variables, units, global WGS 84 grid and 0.05-degree spacing. The v3.0 publication is [Assis et al. (2024), DOI 10.1111/geb.13813](https://doi.org/10.1111/geb.13813). The acquired response's time coordinates are 2000-01-01 and 2010-01-01 UTC; reconcile the product title (baseline 2000–2019), ERDDAP coverage end (2010) and publisher's decadal-statistic description before asserting exact averaging windows or temporal compatibility. The array inspection and limitations are recorded in the [source record](2026-10-09-source-bio-oracle-oceantemperature.md).
- **Decision:** Add a standard-library Bio-ORACLE ERDDAP utility that inspects one dataset's metadata and retrieves a selected grid variable only when the caller provides increasing latitude and longitude bounds. Preserve the returned NetCDF bytes unchanged under `data/raw/bio_oracle/<dataset-id>/` with a timestamped filename, checksum and local query manifest. Use one bounded candidate query—`thetao_baseline_2000_2019_depthsurf`, variable `thetao_mean`, longitude 79–82°E and latitude 5–10°N—as an initial feasibility example. This Sri Lanka-adjacent window is not the modelling domain, an EEZ boundary or a final feature choice. Keep the publisher's full array representation in NetCDF; do not flatten it. Extend CI's syntax compilation to include the new collector, without making CI download data.
- **Rationale:** This begins source access without silently deciding the final species, boundary, depth context or feature set. Explicit bounds reduce the chance of an accidental global download. A direct standard-library ERDDAP client avoids selecting an unadopted package stack and remains compatible with the Python 3.14 project baseline and Python 3.10+ intake floor.
- **Consequences and limitations:** `bio_oracle_layers.py` initially implemented metadata inspection, coordinate-bounded ERDDAP requests, NetCDF retrieval, byte fingerprinting and local query provenance. The initial 8 October request failed because the execution host could not resolve the publisher endpoint; a bounded retry acquired one NetCDF response on 9 October. Its structure, coordinate centers, value/fill counts, query, checksum and byte count remain in the [historical source record](2026-10-09-source-bio-oracle-oceantemperature.md). The user later requested deletion of that test payload and its local manifest; neither is currently retained. The sample was not checked against a marine mask; precise averaging windows, ecological fit and compatibility with occurrences remain unresolved. [D-047](2026-10-09-decision-bio-oracle-catalog-intake.md) expands source-intake code to a full v3 regional catalogue plan. There is no environmental processing, spatial integration, target construction or modelling in this decision.
- **Status:** Initial bounded intake was implemented and sampled; the test payload was later deleted. D-047 expands the current acquisition scope.
