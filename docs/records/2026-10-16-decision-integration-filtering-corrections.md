# Decision D-052 — Integration and temporal-filter correction rules

- **ID:** D-052
- **Date:** 16 October 2026
- **Question:** How should the existing OBIS–Bio-ORACLE integration resolve shared feature units and uncertain observation dates, and how should downstream temporal and marine filtering consume those results?
- **Context:** A read-only implementation audit identified incompatible units for shared temperature/cloud features, ambiguous OBIS date evidence, incorrect handling of JSON-encoded occurrence flags, and a dependency from Script 9 back to Script 8 for grid metadata. The user requested focused corrections, output regeneration, independent source verification and a geographic/environmental diagnostic cross-tab.
- **Options considered:** Retain the first-parseable date and source units; reject incompatible shared variables; or apply source-metadata-based conversions and explicit temporal-resolution rules, retaining unresolved records in the full archive. For Script 9, either re-import integration helpers and reopen NetCDF, or consume the persisted axes and metadata from the full integration output.
- **Evidence and source references:** [Integration summary](2026-10-16-integration-summary.md), [variable catalog](2026-10-16-integration-variable-catalog.md), [integration manifest](2026-10-16-integration-manifest.json), [temporal report](2026-10-16-temporal-filter-report.md), [independent environmental verification](2026-10-16-independent-environmental-verification.md), [geographic/environmental cross-tab](2026-10-16-environmental-coverage-by-geography-and-period.md), and [marine blocker](2026-10-16-marine-filter-blocker.md).
- **Decision:** Preserve every cleaned OBIS row and its original fields in the full GeoParquet. Convert absolute Kelvin air-temperature features to degrees Celsius once after NetCDF automatic decoding; leave temperature ranges unshifted. Standardize cloud-fraction units to dimensionless `1` only where source metadata identifies `TotalCloudFraction`, and validate decoded fraction values against `[0, 1]`. Require compatible standardized units and scientific definitions for shared features. Parse epoch-millisecond date fields by field name; treat multi-year intervals as intervals; resolve them only when reliable point evidence is consistent or the entire interval belongs to one supported environmental period. Mark contradictions and cross-period ambiguity explicitly, retain those rows in the full dataset, and exclude them from strict temporal eligibility. Parse exact `ON_LAND` and `MARINE_UNSURE` entries from the JSON flags; do not use the taxon `marine` attribute or raster match as proof of marine location. Script 9 reads the full GeoParquet and persisted axes/metadata and does not import Script 8 or reopen NetCDF. Create no marine or grid output until an independently sourced, documented marine polygon is provided.
- **Rationale:** The source metadata supports a physical temperature offset for absolute values, not ranges. netCDF4 returns values with declared masking/scaling applied, so the offset is applied only once. Explicit interval rules prevent dates that cross Bio-ORACLE periods from being silently assigned. Persisted axes keep downstream filtering independent from integration. OBIS flags and raster coverage are not an independently validated marine boundary.
- **Consequences and limitations:** The regenerated full output contains 23,371 rows, 112 original OBIS fields, 382 environmental features and 513 total columns. Relative to the former first-parseable-year policy, 694 resolved year values changed and 2 rows changed or became ambiguous in environmental-period assignment. The strict temporal output contains 9,681 records: 651 for 2000–2009, 2,564 for 2010–2019 and 6,466 for 2020–2026; 288 ambiguous records remain in the full archive and are excluded from the temporal output. The independent comparison checked 8,927,722 row-feature positions across 106 source products with zero value or null/fill discrepancies and maximum absolute difference 0. A future-only `clt_sd` source product declares dimensionless units but decodes above 1; its values match the source, but its meaning requires publisher clarification. Exact baseline averaging windows also remain unresolved. No marine polygon is available, so marine and grid outputs remain blocked. These are accepted processing rules for implementation; human scientific acceptance remains pending.
