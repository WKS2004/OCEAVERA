# Contributor and AI-usage recording

Apply to every meaningful AI-assisted repository contribution. Follow the [identity mapping](../../docs/project/ai-team-members.md), [recording template](../../docs/project/ai-usage-log-template.md) and [log index](../../docs/README.md#contribution-records).

1. Resolve the acting GitHub account from authenticated account evidence or the contributor's explicit statement; match its actual name to the canonical mapping. Do not rely on Git display names, email, repository ownership or another member's log. If identity remains unresolved, ask while continuing independent work and do not guess.
2. Complete the authorised work and relevant checks. Log only actual actions; creating a recording system does not authorise member assignments, data acquisition or modelling.
3. Create or append only the acting contributor's exact-username log. Include all ten template fields, the client date/time and timezone, actual agent/tool/model metadata, request, actions, outcome and verification evidence. State unavailable metadata explicitly.
4. Separate retained AI output from human acceptance, human changes and verification. Worktree changes do not prove a commit or publication. State pending review and unrun checks.
5. Preserve prior entries and factual evidence. Amend a record transparently when correction is requested; do not add a separate contribution event for a correction-only task or retrospectively attribute unverified history.

Keep credentials, personal contact details, hidden reasoning and unsupported claims out of logs. Do not create empty logs for other contributors, import another project's activities or generate a member's assessed Personal Learning Journey. Link scientific results to their evidence records; a contribution entry is not proof of model quality or assessment completion.
