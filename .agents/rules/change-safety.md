# Change scope and evidence discipline

Apply to every repository task.

- Inspect the requested scope and existing changes before editing. Preserve work unrelated to the request and use focused searches/reads.
- Keep shared planning work separate from authorised technical stages. A request to improve guidance does not start a member's dataset or modelling work.
- Treat supplied chats and example repositories as reference material. Their recommendations do not establish approval, measured coverage, completed models or this project's selected stack.
- Make complete, reviewable changes within the request. Do not add empty implementations, speculative dependencies or copied deployment rules to make the foundation appear finished.
- Whenever project code, notebooks or required tooling add, remove or change a third-party Python package, update the root `requirements.txt` with its selected exact version in the same change and revise the relevant setup instructions. Do not list standard-library modules or speculative dependencies.
- Do not create, modify or remove Python environments, or install, upgrade or remove Python packages, without explicit user authorisation for that operation in the current task. A requirements-manifest or documentation change does not authorise running environment or package commands. Setup commands are provided for user-led use; do not retain Python environment directories in the repository.
- Record actual AI assistance and review status in the verified acting contributor's log under the [recording rule](ai-usage.md). Do not guess identities, change member allocations without explicit authorisation or claim unevidenced human acceptance. Follow the [canonical member plan](../../docs/project/member-responsibilities.md); its allocated duties are not completed contributions.
- Do not commit, publish, contact stakeholders or broaden external access without the relevant user authorisation.
