# Repository alignment

Read the [maintenance rule](../../rules/repository-maintenance.md), [overview and scope](../../../docs/project/project-overview-and-scope.md), [requirements](../../../PROJECT_REQUIREMENTS.md) and [current status](../../../docs/project/repository-readiness-and-alignment.md).

1. Inspect the worktree and existing changes. Identify actual artefacts, planned support and unsupported completion claims.
2. Compare proposal commitments and assessment obligations against repository evidence. Preserve unresolved choices and the current authorisation boundary. For allocation documentation, use the [overview and linked detailed files](../../../docs/project/member-responsibilities.md); preserve every activity, shared role, proposal provenance and recorded change control without claiming completed work.
3. Improve navigation, directory purpose, records and guidance where gaps exist. Keep local references within the repository; use paths relative to each containing document. Apply [member privacy](../../../CONTRIBUTING.md#member-privacy); preserve responsibility coverage while excluding sensitive academic identity fields and assessment records, subject only to D-042's branch-notebook table exception.
4. Reconcile the overview and scope, decision register, requirement links and status review. Record maintenance/AI assistance in the verified acting contributor's log under the [recording rule](../../rules/ai-usage.md); preserve unattributed history and do not invent member contributions.
5. At branch finalisation, create or update the branch work notebook after code, documentation and requested checks are complete. Follow the [notebook convention](../../../notebooks/README.md#branch-work-notebook-convention); capture actual artefacts, provenance, executed checks and limitations without turning it into an individual contribution reflection. Use native Markdown cells for the title, contributor table, scope, data context and explanations before concise Python Code cells. Execute Code cells in order and retain concise outputs. Input may be a saved file or an explicitly enabled API request; network access is off by default and notebook data stays in memory without writing dataset files. Use a contributor table headed `Registration Number`, `Member Name` and `GitHub Account`. Registration numbers may appear only in that notebook table; omit all other academic identifiers and do not repeat registration numbers in logs or other artefacts.
6. Check reference resolution, skill routing, text formatting and ignore behaviour. Report the alignment judgement, remaining evidence and the limits of the checks.

Return a self-contained status review linked to repository artefacts. Do not implement analytical stages merely to close assessment gaps.
